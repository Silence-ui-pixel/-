# 前端工程骨架 · 技术文档（通俗版）

> 这是给「不太看得懂代码」的人准备的说明文档。
> 目标：看完能明白——这个前端项目由哪些部分组成、它们之间怎么配合、怎么跑起来。

## 一、这个项目是干嘛的

一句话：**一个「仓储智能管理系统」的网页端界面（工作台）**。

现在的状态是「骨架」——就像盖房子先搭好了框架和电路，墙和家具（业务功能、真实数据）还没装。所以你现在看到的页面能点、能跳转、能登录，但查库存、扫码这些功能还是空的占位。

---

## 二、一个前端项目为什么有这么多文件

前端项目看起来文件很多，但可以分成三大类，你只要记住这三类就够了：

| 类别 | 干什么用 | 类比 |
| --- | --- | --- |
| **配置类文件** | 告诉电脑怎么编译、怎么运行 | 房子的施工图纸 |
| **代码类文件** | 真正实现功能 | 砖、墙、家具 |
| **样式类文件** | 控制长什么样子（颜色、间距） | 装修和油漆 |

## 三、核心文件逐个讲

### 1. 入口文件（程序从这里开始）

**`src/main.ts`** —— 整个程序的「总开关」。

它做了三件事：
1. 创建 Vue 应用
2. 装上三个「插件」：Element Plus（现成的 UI 组件库）、Pinia（状态管理）、路由（页面跳转）
3. 把应用挂载到页面上的 `<div id="app">`

> 你可以把它理解为：开机时自动加载所有零件的启动器。

---

### 2. 路由（决定「网址对应哪个页面」）

**`src/router/index.ts`** —— 管理「点菜单跳转到哪一页」。

它定义了一张「网址 → 页面」的对照表：

| 网址 | 页面 | 说明 |
| --- | --- | --- |
| `/login` | 登录页 | 不需要登录就能看 |
| `/dashboard` | 工作台 | 登录后才能看 |
| `/inventory` | 库存查询 | 登录后才能看 |
| `/pda` | PDA 扫码 | 登录后才能看 |

另外它还有个「**门卫**」功能（代码里的 `router.beforeEach`）：每次跳转前检查一下你有没有登录，没登录就把你拦去登录页。

---

### 3. 登录与状态管理（记住「我是谁」）

**`src/stores/auth.ts`** —— 管理「当前登录用户」的信息。

它负责：
- 存「假 token」（现在没接后端，所以是假的）
- 记住用户名、显示名、角色
- 提供 `login`（登录）和 `logout`（退出）两个动作
- 把登录状态存到浏览器的 `localStorage`（关掉浏览器下次打开还在）

> 这个文件用了一个叫 **Pinia** 的库，Pinia 的作用就是「全局共享一份数据」，任何页面都能读到「当前登录的是谁」。

---

### 4. 布局（页面的「骨架」）

**`src/layout/index.vue`** —— 登录后看到的那个「左边菜单 + 顶栏 + 中间内容」的大框架。

它分成三块：
- **左边**：侧边菜单（工作台 / 库存查询 / PDA 扫码）
- **顶上**：折叠按钮、页面标题、右上角用户名下拉
- **中间**：真正显示内容的区域（会跟着菜单切换）

> 关键点：中间这块用了 `<router-view />`，意思是「这里显示哪个页面，由路由决定」。你点「库存查询」，中间就换成库存查询页。

---

### 5. 各个页面（views 文件夹）

`src/views/` 下面是每个具体页面，目前有 4 个：

| 文件 | 页面 | 当前状态 |
| --- | --- | --- |
| `login/index.vue` | 登录页 | ✅ 能登录（假） |
| `dashboard/index.vue` | 工作台 | ✅ 有统计卡片和进度 |
| `inventory/index.vue` | 库存查询 | ⚠️ 占位，等接数据 |
| `pda/index.vue` | PDA 扫码 | ⚠️ 占位，等接数据 |

---

### 6. 类型定义（给数据「定规矩」）

**`src/types/models.ts`** —— 定义了这个系统里所有「数据长什么样」。

比如「库存」这个数据，规定了它有这些字段：

```
库存（Inventory）：
  - skuId      商品编号
  - qtyOnHand  现有数量
  - qtyAllocated 已锁定数量
  - qtyAvailable 可用数量（= 现有 - 锁定）
  ...
```

> 这个文件的来源很关键：它是**从 A 同事写的数据库表结构（`db/schema(1).sql`）反推出来的**。
> 好处是：前端和后端对「库存」的理解完全一致，不会出现「你说东我说西」。
>
> 注意：这些是「临时占位」，等 A 的正式契约（OpenAPI 文档）出来后，会用自动生成的类型替换掉。

---

### 7. 配置文件（不用细看，知道存在就行）

| 文件 | 作用 |
| --- | --- |
| `package.json` | 列出项目依赖了哪些库、有哪些命令（`npm run dev` 等） |

| `src/styles/index.css` | 全局样式（定义了主题色等） |

## 四、这些文件是怎么「串起来」的（一张流程图）

```
浏览器打开 http://localhost:5173
        │
        ▼
    index.html  →  加载 main.ts（总开关）
        │
        ▼
    main.ts 装上「路由 + Pinia + Element Plus」
        │
        ▼
    路由门卫检查：登录了吗？
        │
   ┌────┴────┐
   │ 没登录   │ 登录了
   ▼         ▼
 登录页   布局 layout（侧边菜单 + 顶栏）
             │
             ▼
      中间显示当前路由对应的页面（工作台/库存/PDA）
             │
             ▼
      页面用 Pinia 读「我是谁」，用 models.ts 定「数据长啥样」
```

**一句话理解**：`main.ts` 是开关 → `router` 决定去哪页 → `layout` 是外壳 → `views` 是每页内容 → `stores` 管登录信息 → `types` 定数据规矩。

## 六、常见疑问

**Q：为什么登录不用真实密码？**
现在没接后端，后端（A 同事负责）还没做好。所以先用一个「假 token」占位，等后端好了再换成真实登录。

**Q：`.vue` 文件是什么？**
Vue 的一个特色：**一个文件里同时写「结构（HTML）+ 逻辑（JS）+ 样式（CSS）」**，一个 `.vue` 文件就是一个完整的小组件。

**Q：我该重点看哪几个文件？**
如果是想看懂骨架，重点看这 4 个就够了：
1. `src/main.ts`（入口）
2. `src/router/index.ts`（路由）
3. `src/layout/index.vue`（布局）
4. `src/stores/auth.ts`（登录状态）

其余的先有个印象就行。
