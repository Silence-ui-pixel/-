> 文档定位：B 侧前端（`B_project`）的导航与信息架构设计稿 + 进度盘点 + 下一步计划。
> 阅读对象：B（交互与智能）、A（后端底座）、以及后续接手的编码代理。
> 更新时间：2026-10-25

## 一、设计目标与原则

这套导航体系不是「摆几个菜单项」，而是整个工作台的**信息架构骨架**。它要回答三个问题：**用户进来先看什么、怎么最快到达任务、系统将来长成什么样**。

设计原则（与项目铁律、用户偏好对齐）：

1. **按「业务动线」组织，不按「功能」罗列**——菜单顺序就是仓库一天的作业顺序：先看全局（工作台）→ 查货（库存）→ 干活（入库/出库/PDA）→ 兜底（系统）。
2. **菜单即路由，路由即权限**——菜单结构、前端路由、后端 RBAC 三者共用同一份「元数据」，避免三处各写一遍导致漂移。
3. **契约先行**——凡是依赖 A 数据的菜单/页面，一律先占位、用 Mock 跑通，等 openapi 出来再接真数据，不阻塞 UI 推进。
4. **深色低饱和 + 纯 CSS 动画 + 无障碍**——沿用既定视觉偏好，不引入重型动画库。
5. **LLM 只读、人审批**——工作台上的「AI 建议」只展示，不落写库动作。

### 2.1 菜单全景（目标态，非一次性全做）

```
仓储智能管理工作台
│
├── ① 工作台 Dashboard          —— 登录后的落地页，全局概览
│
├── ② 库存 Inventory             —— 「查货」域
│   ├── 库存查询 InventoryQuery
│   ├── 库存流水 StockTxn
│   └── 盘点任务 CountTask（占位）
│
├── ③ 入库 Inbound               —— 「收货」域（占位）
│   ├── 入库单管理 InboundOrder
│   └── 收货上架 ReceivingPutaway
│
├── ④ 出库 Outbound              —— 「发货」域（占位）
│   ├── 出库单管理 OutboundOrder
│   ├── 波次拣货 WavePicking
│   └── 复核打包 PackVerify
│
├── ⑤ PDA 作业 PDA（独立入口）   —— 移动端 H5，桌面侧栏仅作入口跳转
│
└── ⑥ 系统管理 System（受 RBAC 控制，仅 ADMIN 可见）
    ├── 用户与角色 UserRole
    ├── 商品主数据 SkuMaster
    ├── 库位管理 LocationMaster
    └── 审计日志 AuditLog
```

### 2.2 菜单分组的落地节奏

| 分组 | 状态 | 依赖 | 优先级 |
| --- | --- | --- | --- |
| ① 工作台 | ✅ 已有骨架 | 无 | P0 |
| ② 库存（查询/流水） | 🟡 查询占位、流水待建 | 库存接口契约 | P1 |
| ③ 入库 | ⬜ 未建（占位） | 入库单契约 | P2 |
| ④ 出库 | ⬜ 未建（占位） | 出库单契约 | P2 |
| ⑤ PDA | 🟡 有占位页 | Mock | P2 |
| ⑥ 系统管理 | ⬜ 未建 | RBAC 后端 | P3 |

> 结论：**菜单树「一次规划到位」，但页面「分期填充」**。侧栏可以先把目标分组搭出来、空分组折叠/置灰，避免以后反复改菜单结构。

### 3.2 当前技术债 / 待改进点（这是本次方案要解决的核心）

1. **菜单硬编码在 layout 里**——`menus` 数组与 `router` 的 `meta` 各写一份，重复且易漂移。
2. **菜单没有「配置化」**——加一个页面要同时改两处（router + layout 的 menus），违反「单一数据源」。
3. **没有权限过滤**——菜单/路由还没接 RBAC，`auth.user.role` 目前只显示、不拦截。
4. **无面包屑 / 无标签页（tabs）**——多级菜单展开后，用户不知道自己在哪、无法快速切换。
5. **PDA 与桌面共用同一套导航**——移动端应走独立壳，避免桌面侧栏在小屏塌掉。
6. **图标用字符串映射 `<component :is>`**——可维护性一般，需统一注册方式。

## 四、专业改造方案（菜单 + 路由 + 布局）

### 4.1 单一数据源：路由表即菜单源（Route-driven Menu）

**核心思路**：不再在 layout 里手写 `menus` 数组，而是**从路由表自动生成菜单**。路由的 `meta` 承载菜单所需的一切信息（标题、图标、排序、是否隐藏、所需角色）。

```ts
// src/router/routes.ts（示例结构）
export interface AppRouteMeta {
  title: string
  icon?: string
  sort?: number        // 菜单排序
  hidden?: boolean     // 不在菜单显示（如 404）
  roles?: UserRole[]   // 空 = 所有人可见；非空 = 仅这些角色
  public?: boolean     // 免登录
  keepAlive?: boolean  // 是否缓存页面
}

export const menuRoutes: RouteRecordRaw[] = [
  {
    path: '/', component: Layout, redirect: '/dashboard',
    children: [
      { path: 'dashboard', name: 'dashboard', meta: { title: '工作台', icon: 'Odometer', sort: 1 } },
      {
        path: 'inventory', name: 'inventory', meta: { title: '库存', icon: 'Box', sort: 2 },
        children: [
          { path: 'query', name: 'inventory-query', meta: { title: '库存查询', sort: 1 } },
          { path: 'txn', name: 'inventory-txn', meta: { title: '库存流水', sort: 2 } },
        ],
      },
      // ... 入库 / 出库 / 系统管理 同构展开
    ],
  },
]
```

**好处**：加页面只改路由一处，菜单自动跟着变；`roles` 一处控制「菜单显示」与「路由拦截」两件事。

### 4.2 菜单渲染组件（递归）

```ts
// src/layout/components/SideMenu.vue
// 递归渲染：父级有 children → el-sub-menu；叶子 → el-menu-item
// 依据 auth.user.role 过滤 meta.roles
```

要点：
- 按 `meta.sort` 排序；`hidden: true` 的项跳过。
- 无权限的项整组过滤（连父级一起隐藏）。
- 图标从 `@element-plus/icons-vue` 统一 `app.component` 注册，`<component :is>` 直接引用，避免字符串查找。

### 4.3 布局升级：三段式 + 面包屑 + 标签页

```
┌─────────────────────────────────────────────┐
│ 顶栏 header（56px）：折叠 | 面包屑 | [标签] 用户 │
├──────┬──────────────────────────────────────┤
│ 侧栏 │  标签页 TabsBar（可选，多页切换）        │
│ logo │──────────────────────────────────────┤
│ 菜单 │  内容区 <router-view>（keep-alive）     │
│ 220px│                                      │
└──────┴──────────────────────────────────────┘
```

新增三个能力：

1. **面包屑（Breadcrumb）**——由 `route.matched` 自动生成，解决多级菜单「我在哪」。
2. **标签页（TabsBar）**——记录已打开的页面，支持关闭、右击关闭其他；配合 `keep-alive` 缓存页面状态（如库存查询的筛选条件）。
3. **响应式**——小屏（<768px）侧栏自动收起为抽屉或图标态；PDA 走独立壳，不进这套桌面布局。

### 4.4 权限体系（RBAC 三层联动）

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 菜单层 | SideMenu | `meta.roles` 过滤菜单项 |
| 路由层 | `router.beforeEach` | 无权限访问 → 重定向 /dashboard 或 403 |
| 接口层 | 后端 + API client | 最终兜底（前端只做体验层拦截，不替代后端鉴权） |

角色映射（沿用 `models.ts` 的 `UserRole`）：
- `ADMIN`：全部（含系统管理）
- `MANAGER`：工作台 + 库存 + 入库/出库
- `OPERATOR`：工作台 + 库存 + PDA
- `VIEWER`：只读（工作台 + 库存查询，无写操作入口）

## 五、工作台（Dashboard）布局升级方案

现状工作台只有「统计卡片 + 步骤条」，信息密度偏低。建议升级为**四区块布局**：

```
工作台 Dashboard
├── A 顶部：4 个 KPI 统计卡（SKU 数 / 库位数 / 库存条目 / 待办任务）
├── B 中部左：Sprint 进度（沿用现有 el-steps，数据接任务清单）
├── B 中部右：AI 助手面板（只读：异常库存提醒、待审批事项）
├── C 底部：近期动态 / 库存预警列表（占位，接 Mock）
```

关键原则：**AI 面板只「建议」不「执行」**，任何写库动作必须跳转到具体业务页 + 人工确认，呼应「智能与操作权限分离」铁律。

## 七、给后续代理的执行约定

1. **改菜单/路由，只改 `routes.ts` 一处**，禁止再往 layout 里手写 menus 数组。
2. **新增页面流程**：加路由（含 meta）→ 自动进菜单 → 建 `views/xx/index.vue` → 用 Mock 跑通 → 接真数据。
3. **权限**：前端只做体验层过滤，后端鉴权才是兜底；`meta.roles` 与后端 RBAC 口径保持一致。
4. **视觉**：深色低饱和、纯 CSS 动画、SCSS 变量、`prefers-reduced-motion` 适配。
5. **PDA**：走独立移动壳，不复用桌面侧栏布局。
