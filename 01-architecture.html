仓储智能管理 Agent 系统 · 总体架构

WMS 业务底座 + 数据与 IoT 感知层 + AI Agent 智能决策层，四层解耦、自下而上逐级赋能
核心范式：AI 建议 · 人审批 · 动作可审计
L1
接入层
接入层 · Access
人、设备、系统三个方向的统一入口
运营 Web 工作台 PDA / 手持终端 大屏看板 语音 / IM 助手 开放 API / Webhook
L2
智能层
AI Agent 智能层 · 核心差异化
编排器拆解意图 → 专业 Agent 推理 → 治理链校验 → 工具执行
编排器 Orchestrator · Planner / Router 短期记忆 · 会话上下文 RAG 知识库 · SOP / 作业手册
专业 Agent 集群（按运营角色划分边界）
库存查询 Agent 补货预测 Agent 上架 / 拣货 Agent 排班调度 Agent 安全合规 Agent SOP 问答 Agent
MCP 工具层（唯一可写入口，白名单）
查库存 建收货单 建波次 库存调整 发通知 读设备状态
工具入参强类型校验，超出策略包络直接拒绝
治理链 模型网关 ModelGateway→ 决策引擎 DecisionEngine→ 人机审批 HITL→ 动作执行 ActionExecutor 模型：本地 / 云端 LLM 双路由
L3
业务层
业务应用层 · WMS 底座
所有 AI 动作最终落到这里的标准业务单据
入库：预约 / ASN → 收货 → 质检 → 上架 出库：订单 → 波次 → 拣货 → 复核 → 打包 → 发运 库内：移库 / 调拨 / 库存调整 盘点：循环盘点 / 差异处理 库存台账 · 批次效期 报表与看板
L4
算法层
算法与策略层
确定性的运筹优化，与 LLM 推理分离，保证结果可复现
库位分配 波次策略 拣货路径优化 需求预测 安全库存 / 补货点 FEFO / FIFO 规则 装载与车辆调度
L5
数据层
数据层
结构化事务 + 向量语义 + 时序遥测，三类存储各司其职
关系库 PostgreSQL / MySQL 缓存 Redis 向量库 pgvector / Milvus 时序库 TimescaleDB 对象存储 · 单据影像 数仓 / BI 数据集市
L6
感知层
感知与设备层
实物世界的入口，数据实时性与幂等性是工程难点
条码 / 二维码扫码 RFID 通道门 电子标签 PTL AGV / AMR 温湿度 / 冷库传感 电子秤 / 称重 视频与视觉识别
横向治理与安全
贯穿六层，非可选模块
身份与权限 RBAC
用户 / 角色 / 数据行级隔离，多仓多货主场景必备
审计与全链路追溯
每条 AI 建议、审批、执行的完整证据链，可回放
AI 护栏 Guardrails
提示注入防护、越权动作拦截、输出合规校验
可观测与告警
指标 / 日志 / 链路追踪，模型调用成本与延迟监控
容灾与备份
库存账实一致性校验、定时快照与恢复演练
关键约束
LLM 不直接持有写权限；确有风险的动作强制进入人工审批队列，且审批单可过期、单次有效
外部系统与上下游 经 API / 中间件集成，不直接访问内部数据库
ERP · SAP / 用友 / 金蝶 OMS 订单中心 TMS 运输管理 电商平台 / 门店 供应商协同 SRM WCS / 设备控制系统 企业微信 / 邮件通知
设计原则：智能与操作权限分离 —— AI 可以在策略包络内自适应推理，但任何改变实物状态的动作都必须确定性校验、显式审批、事后可审计。
