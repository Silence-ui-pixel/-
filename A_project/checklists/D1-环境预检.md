## 四、今天发现并修掉的 3 个问题

### 缺陷 1：种子数据不可重复导入

**现象**：`seed.sql` 第二次执行报 `duplicate key value violates unique constraint "uk_user_username"`。

**影响**：本地开发、CI 建库、演示环境重建都会重复跑播种。一次 duplicate key 就足以让新人卡半小时，而且会误判成"数据库坏了"。

**修复**：每条 insert 加 `on conflict ... do nothing`，用各自的业务唯一键做冲突目标。

### 缺陷 2：DDL 与种子数据混在一个文件里（结构性问题）

**现象**：修好幂等后，第二次执行整个 `schema.sql` 仍然报 `relation "app_user" already exists`。

**根因**：`schema.sql` 里既有 `create table`（只该跑一次），又有 `insert`（要能反复跑）。混在一起就只能二选一：

- 整个文件不可重跑 → 现在的问题
- 把 DDL 改成 `create table if not exists` → 会**掩盖结构不一致**，比第一个更危险（表结构变了但没人知道）

**修复**：拆成两个文件。

```
db/schema.sql    建结构（只跑一次）
db/seed.sql      播种（可重复跑，全部 on conflict do nothing）
```

这个拆分对 S1-06 很重要：**alembic 迁移只覆盖 `schema.sql` 的 DDL，`seed.sql` 由脚本单独调用**。两者生命周期不同，就不该放一个文件里。

### 问题 3：Windows 端口保留导致 `docker run` 失败（脚本健壮性缺陷）

**现象**：Docker Desktop 启动后重跑，卡在第一步：

```
[FAIL] 容器启动失败（端口 55432 可能被占用，试试 PORT=55433）
```

**误判方向**：以为端口被别的进程占用。但 `netstat` 查不到任何进程在监听 55432。

**真因**：Docker 的原始报错被脚本吞掉了，实际是

```
docker: Error response from daemon: ports are not available:
listen tcp4 127.0.0.1:55432: bind: An attempt was made to access
a socket in a way forbidden by its access permissions.
```

这是 Windows 的 **Hyper-V / WinNAT 动态端口保留**。本机排除段实测：

```
55348–55447 · 55448–55547 · 55548–55647 · ... · 56148–56247
```

**连续覆盖 900 个端口**，55432 正好落在第一个段里。

**两层修复**：

1. **脚本根本不需要发布端口。** 全部操作都通过 `docker exec` 在容器内跑 `psql`，从没用到 `127.0.0.1:55432`。默认去掉 `-p` 参数，端口问题彻底消失
2. 确实需要外部客户端连接时用 `PUBLISH=1`，脚本读 `netsh` 的排除段自动避让。注意避让不能做「起始端口 +N 线性探测」——因为保留段连续 900 个，探测 40 个全在里面。改成优先退回常规端口（5432 / 5433 / 15432 …）

**同时修掉一个更根本的问题：脚本不该吞掉 Docker 的原始报错。** 原来的 `>/dev/null 2>&1` 把「端口保留」伪装成了「端口占用」，排查方向直接被带偏。现在失败时会打印原始报错并给出针对性诊断（端口保留 / 同名容器 / 镜像缺失 / 守护进程未就绪）。

> 教训：**诊断信息被吞掉时，错误提示本身会变成误导。** 一条 `2>&1` 的省略，代价是半小时的错误方向。

## 六、常见报错对照

| 报错 | 原因 | 处理 |
|---|---|---|
| `duplicate key ... uk_*` | 播种不幂等 | 该条 insert 缺 `on conflict` |
| `relation "xxx" already exists` | 对已建库重跑 DDL | 用新库，或只跑 `seed.sql` |
| `null value in column "batch_no"` | 显式传了 NULL | 用空串 `''` 作哨兵值 |
| `column "qty_after" does not exist` | 列名记错 | 实际是 `after_on_hand` / `before_on_hand` |
| `stock_txn 是只追加账本，禁止 UPDATE 操作` | 触发器正常工作 | **不是错误**，是想改历史的操作被正确拒绝 |
| `v_inventory_recon` 出现 `ONLY_INVENTORY` | 余额有、流水无 | 有人绕过流水直接 INSERT 了 inventory |
| `v_inventory_recon` 出现 `MISMATCH` | 余额 ≠ 流水累计 | 有代码绕过了 `apply_txn` 直接 UPDATE |
| `ports are not available ... access permissions` | Windows 保留端口段（不是端口占用） | 去掉 `-p`；或 `PUBLISH=1`；或管理员 `net stop winnat && net start winnat` |
| `Bind for 0.0.0.0:xxxx failed: port is already allocated` | 真的被别的容器占了 | `docker ps` 找到它，或换端口 |
