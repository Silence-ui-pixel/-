## 线框图 1：库存查询页｜PC 为主（查询/看流水），PDA 只读速查（P2 可选）

**【筛选区】**
- 商品：SKU 编码 / 名称 / 条码 模糊搜 `→ sku.sku_code / name / barcode`
- 库位：全码 / 库区 `→ location.location_code / zone_code`
- 库位类型 `→ location.location_type`（STORAGE 存储位 / RECEIVING 收货暂存 / PICKING 拣货位 / STAGING 发货暂存 / QUARANTINE 隔离）
- 批次 `→ inventory.batch_no`
- 效期预警：`N 天内到期` 开关 `→ I1 的 expiring_days`
- 只看有货（可用库存 > 0）

**【列表/展示字段】**
- SKU 编码 + 名称 + 规格 `→ sku`
- 库位全码 `→ location.location_code`
- 批次 / 效期 `→ inventory.batch_no / expiry_date`
- **现有库存** `→ qty_on_hand`
- 已分配（锁定） `→ qty_allocated`
- **可用库存** `→ qty_available`（生成列，只读）
- 单位 `→ sku.base_uom`

**【操作按钮/步骤】**
- 查询 / 重置（PC）
- 点行 → 看该维度流水（跳 I2，按 sku+库位+批次过滤，PC）

**【备注】**
- ⚠️ 措辞统一：主列显示「**可用库存**」，旁边给「现有库存」「已分配」作参考；**全文不出现「可拣库存」**。可用 = 现有 − 锁定。
- `qty_available` 是生成列，前端**只读**，不反算提交。
- 对应接口：I1（+ I2 流水）。PDA 端本页只做只读速查，不做操作。
- ⚠️ 「收货即落账」后，暂存位（RECEIVING）的货「可用库存」已 >0，会出现在查询结果里（货确已在库，正确），但作业员可能困惑；故提供「库位类型」筛选，默认可排除 RECEIVING 暂存位。

## 线框图 2：入库作业台（收货→上架）｜建单/改单/看进度 = PC；收货扫码/上架扫码 = PDA

> 前端只暴露 4 个可见状态：`DRAFT → RECEIVED → PUTAWAY → DONE`（中间态后端内部流转）

**【筛选区】（PC 列表）】**
- 单号 `→ order_no`、供应商 `→ supplier_name`、类型 `→ order_type`(PO/RETURN/TRANSFER)、状态 `→ status`

**【列表字段】（PC）】**
- 入库单号、类型、供应商、状态、预计到货 `→ expected_at`、应收/实收 `→ total_expected_qty / total_received_qty`

**【操作按钮/步骤】**
- PC：新建入库单（B2，头+明细一次提交，DRAFT）、改明细数量（B4，仅 DRAFT）、取消（B7，仅 DRAFT/ARRIVED）
- PDA 收货（B5）：
  1. 扫入库单 → 显单头
  2. 扫 SKU 条码 `→ sku.barcode` → 显示【商品名、应收 `qty_required`、已收 `qty_actual`、剩余待收】
  3. 输实收数 + 批次 `batch_no`（`is_batch_managed` 商品必填）+ 效期 `expiry_date`
  4. 确认 → 入收货暂存位（`location_type=RECEIVING`），DRAFT→RECEIVED，走 `apply_txn`(RECEIPT)
  5. 不良数单独记 `qty_rejected`（支持部分收货）
- PDA 上架（B6）：
  1. 扫收货单 → 系统按策略给目标库位
  2. 显示建议库位 `→ to_location_id`
  3. 扫实际库位码校验是否一致
  4. 确认上架 → 暂存位转存储位，RECEIVED→PUTAWAY，走 `apply_txn`(PUTAWAY)
  5. 全部上架完 → DONE

**【备注】**
- 端区分：建单/改明细/看进度 = PC；收货扫码/上架扫码 = PDA。
- 幂等：`receive / putaway` 必须带 `Idempotency-Key`（PDA 弱网重试）。
- 措辞：应收 `qty_required` / 实收 `qty_actual` / 不良 `qty_rejected`，数字字段对外统一。
- 部分收货后单据状态**仍为 RECEIVED（可继续收）**，全部明细收完才推进 PUTAWAY。
- 对应接口 B1–B7；数据出处 `inbound_order / order_line / location / stock_txn`。

## 线框图 3：出库作业台（分配→拣货→发运）｜建单/分配/发运 = PC；拣货扫码 = PDA

> 可见状态：`DRAFT → ALLOCATED → PICKING → PICKED → SHIPPED`

**【筛选区】（PC 列表）】**
- 单号 `→ order_no`、客户 `→ customer_name`、状态 `→ status`、优先级 `→ priority`

**【列表字段】（PC）】**
- 出库单号、类型、客户、状态、优先级、要求发货日 `→ requested_ship_at`、总量 `→ total_qty`

**【操作按钮/步骤】**
- PC：新建出库单（O2）、**分配库存**（O4，**按明细行分配**，按 FEFO 锁批次，只动 `allocated_delta`，失败返回 409 + 可用量明细）、取消（O7，DRAFT/ALLOCATED，ALLOCATED 取消回滚走 `DEALLOCATE` 流水，`allocated_delta` 负）
- PDA 拣货（O5）：
  1. 扫出库单
  2. 系统返回拣货路径（按 `location.pick_seq` 排序），**返回字段：SKU编码、库位全码、应拣数、批次、效期**
  3. 逐行显示【SKU、库位 `location_code`、应拣 `qty_required`、批次、效期】
  4. 扫库位校验 → 扫 SKU → 输实拣 `qty_actual`（短拣记 `qty_rejected`）
  5. 逐行确认 → PICKED，走 `apply_txn`(PICK：`allocated_delta` 负、`on_hand` 不动)
- PC 发运（O6）：确认发运 → 扣减在途 + 落 `stock_txn`(SHIP)，状态→SHIPPED；填承运 `carrier` / 运单号 `tracking_no`

**【备注】**
- 端区分：建单/分配/发运 = PC；拣货扫码 = PDA。
- 幂等：`pick / ship` 带 `Idempotency-Key`。
- ⚠️ O4 分配是并发超卖高风险接口，前端要专门处理「分配失败」的 409 错误结构（展示可用量明细）。
- 措辞：应拣 `qty_required` / 实拣 `qty_actual` / 短拣 `qty_rejected`。
- 对应接口 O1–O7；数据出处 `outbound_order / order_line / location / stock_txn`。
