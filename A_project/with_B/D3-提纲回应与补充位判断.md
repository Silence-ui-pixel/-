## 二、5 个补充位的判断（逐条）

B 留了 5 个空位让我填。我的判断如下：

### 补充位 1：**入库单的「预计到货 expected_at」要出现在 PDA 收货页吗？** → 需要，但契约已有

- B 提纲里 PDA 收货页「扫入库单→单头」只写了「供应商、应收合计」，**漏了 `expected_at`（预计到货日）**。
- 仓库收货员扫单时，第一件事就是看「这单该今天到吗」，预计到货日是收货页单头**必须显示**的字段。
- **契约里 `InboundOrder.expected_at` 已有**，不需要改契约，但 B 做 PDA 页时要记得显示这一项。

### 补充位 2：**出库拣货页要不要显示「拣货路径顺序号 pick_seq」？** → 不需要显示，系统内部用

- PDA 拣货是「系统按 pick_seq 排序后返回」，操作员**只看顺序跟着走**，不需要看到 pick_seq 数字本身。
- 契约里 `pick_seq` 在 Location schema 里有，但拣货路径接口（PickPlanResponse）**不返回 pick_seq**，这是对的——操作员不需要这个数字。
- 结论：**不补**。

### 补充位 3：**PDA 收货页要不要显示「已收/应收进度条」？** → 建议加，但属前端展示，不改契约

- B 写了「已收 qty_actual、剩余待收」，这个「剩余待收」=`qty_required - qty_actual`，是前端算出来的，契约已提供两个原始字段。
- 进度条是纯前端渲染，**不需要契约加字段**。
- 结论：**不补契约，B 前端自己算**。

### 补充位 4：**出库单「分配」后，PDA 拣货页要显示「已分配批次/效期」吗？** → 需要，契约已覆盖

- B 拣货页写了「应拣数、批次、效期」，但**批次/效期是「分配」步骤锁定的结果**，拣货时必须显示锁定的是哪个批次、哪个效期（否则 FEFO 拣错）。
- 契约里 `PickLine` 已含 `batch_no`、`expiry_date`，**已覆盖，不需要改**。

### 补充位 5：**入库单「上架」后要不要显示「最终库位」？** → 需要，且这是唯一值得确认的一点

- B 上架环节写了「扫实际库位码校验是否一致」，但没写「上架完成后，单上要显示最终落位的库位」。
- 仓库后续查「这货放哪了」靠的就是 order_line 的 `to_location_id`。
- 契约里 `OrderLine.to_location_id` **已有**，上架成功后返回的单据详情会带上。
- 结论：**已覆盖，但 B 做上架完成页时要显示「最终库位」，方便复核**。
