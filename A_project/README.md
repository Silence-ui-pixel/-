## 五、四条红线

1. **不要先写业务逻辑再补契约。** 两人分工下契约是协作合同，不是实现副产物。顺序反了整个 Sprint 都在返工。
2. **不要让 B 绕过接口直接读表。** 他连一次库，你的表结构就再也改不动了。
3. **不要把 apply_txn 写成"更新一下库存"。** 必须：行锁 → 校验可用量 → 写余额 → 写流水 → 同一事务提交。
4. **不要一个人改表结构。** 冻结后改表必须两人同时在场，否则 B 的 mock 和类型全废且他不知道。

## 七、已完成：环境验证（2026-10-24）

在真实 PG 引擎上跑通 `schema.sql` + `seed.sql`，**20 项断言全部通过**：8 张表、对账视图全 OK、UPDATE/DELETE 被触发器拦下、播种 3 次不重复累加、负库存与不自洽快照被 CHECK 拦下、`batch_no = NULL` 被 NOT NULL 拦下。

过程中修掉两个真实缺陷：

1. **种子数据不可重复导入** — 第二次执行报 `duplicate key ... uk_user_username`。已给每条 insert 加 `on conflict do nothing`。
2. **DDL 与种子混在一个文件** — 拆成 `db/schema.sql`（建结构，一次）+ `db/seed.sql`（播种，可重复）。这个拆分对 S1-06 也重要：alembic 只覆盖 DDL。

全部细节见 `checklists/D1-环境预检.md`。

> **真实 PG 16 已补跑通过（22:40）。** `verify-schema.sh` 在 Docker 的 postgres:16 上全部通过，与离线版结论一致，无版本差异。
>
> 补跑时踩到一个 Windows 特有的坑：**Docker 的 `-p` 端口映射撞上 Hyper-V/WinNAT 保留段**（本机 55348–56247 连续 900 个端口被占），报 `access permissions` 而非"端口占用"。已改为**默认不发布端口**（脚本全程走 `docker exec`，不需要暴露），需要外部连接时 `PUBLISH=1` 自动避让。同时修掉"脚本吞掉 Docker 原始报错"的问题——那条 `2>&1` 让排查方向偏了半小时。

**注意：本目录不放共享文件的副本。** `contracts/`、`db/`、`03-data-model.html` 都在项目根目录，A 直接在那里改，本目录只放草稿和个人记录。

### 交付给 B 的东西已就位

### 过程中修掉的 4 个问题

1. **`/sql/schema.sql` 路径被 MSYS 改写** — Git Bash 把以 `/` 开头的参数当 Windows 路径转换，`psql -f /sql/schema.sql` 变成 `D:/GitHub_Projects/.../sql/schema.sql`。改用 **stdin 重定向** `< db/schema.sql`，完全不经过路径转换，跨 shell 一致
2. **ruff B008** — FastAPI 的 `Depends()` 在参数默认值里是标准写法，用 `extend-immutable-calls` 精确豁免，而不是关掉整条规则
3. **脚本函数定义位置** — `dev.sh` 里 `cmd_db_check` 定义在 `case` 之后，bash 顺序执行时还没定义就调用了。已移到前面
4. **脚本缺执行位** — git 在 Windows 上记录为 `100644`，Linux/CI 上不能直接执行。用 `git update-index --chmod=+x` 改为 `100755`

### 两个刻意的决定

**Makefile 只做转发。** 本机没装 make，所以命令逻辑放在 `scripts/dev.sh`，Makefile 每行只是 `@bash scripts/dev.sh xxx`。两份独立实现必然漂移，不如只留一份真源。

**compose 里不写 web 服务。** 只留注释占位。目录名、构建命令、端口是 B 的决定权，A 写死等于替 B 做技术选型，后面必然返工。
