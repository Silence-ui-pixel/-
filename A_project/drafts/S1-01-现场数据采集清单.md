## 二、A 类：主数据（直接进 `sku` / `location` / `app_user` 表）

### A1｜SKU 清单 〔P0，全量〕

**从哪拿**：现有进销存系统导出 / 仓库的 Excel 台账 / 采购部商品目录

**要这些列**（表头直接用系统字段名，收回来能直接导入）：

```
sku_code, barcode, name, spec, category, base_uom,
weight_kg, shelf_life_days, is_batch_managed, safety_stock, reorder_point, abc_class
```

**每个字段怎么填 / 现场重点确认什么**：

| 字段 | 现场要知道的 | 如果拿不到 |
|---|---|---|
| `sku_code` | 他们现在用什么编码规则？有没有重复？ | 要现场定规则，**不能我们凭空编**（编了和他们对不上） |
| `barcode` | 是厂商条码还是自编？一个 SKU 是不是只有一个条码？ | **重点查**：有没有"一码多品"或"一品多码" |
| `spec` | 规格怎么表达？`550ml*24/箱` 还是分两个字段？ | 我们只有一个文本字段，如果他们是"容量+包装数"两列，要确认能否合并 |
| `base_uom` | 基础单位是什么？有没有"箱/托"换算？ | **重点查**：有没有 1 托 = N 箱的关系（当前系统不支持多单位换算） |
| `shelf_life_days` | 保质期天数从哪天算起（生产日/到货日）？ | 默认按生产日，要确认 |
| `is_batch_managed` | **哪些商品需要管批次，哪些不需要？** | 这是 FEFO 和收货必填批次的前提 |
| `safety_stock` / `reorder_point` | ⚠️ **他们现在有安全库存的概念吗？有没有具体数值？** | **这是 P2 补货建议的燃料**，没有这两个数，AI 建议算不出来 |
| `abc_class` | 有没有 ABC 分类？依据是什么（出库量/金额）？ | 没有就留空，不影响 |

> ⚠️ **最重要的一个问题**：`safety_stock` 和 `reorder_point` 如果现场答"没有这个概念"，那 P2 的「AI 补货建议」需要改成"系统先攒 3 个月出库数据，再自动算出建议补货点"——这会让 P2 工作量 +1 天。**必须在现场问清。**

### A2｜库位清单 〔P0，全量〕

**从哪拿**：仓库的库位表 / 现场逐区登记 / WMS 导出

```
warehouse_code, zone_code, rack_code, level_no, bin_code, location_type,
capacity_qty, is_mixed_sku, is_mixed_batch
```

**现场重点**：

| 要确认 | 为什么 |
|---|---|
| **实际库位编码规则** | 我们现在假设 `WH01-A-01-03`（仓-区-架-层-位），如果他们是 `A0103` 这种，要改结构或加映射 |
| **哪几个位置是收货暂存区** | 对应 `location_type=RECEIVING`，收货必须落在这里 |
| **哪几个是发货暂存区** | 对应 `STAGING`，拣完货放这里 |
| **有没有隔离区**（待检/不良品） | 对应 `QUARANTINE`，没有的话不良品放哪要问 |
| **一个库位能放几个 SKU / 几个批次** | 对应 `is_mixed_sku` / `is_mixed_batch`，影响分配算法 |
| **库位有没有容量上限** | 对应 `capacity_qty`，没有就留空 |

**必拍照片**（每类库位 1-2 张）：
- 库位标签特写（看清编码格式和字体）
- 整排货架全景（看层级和排列）
- 收货暂存区（看实际怎么堆的）

### A3｜用户与角色 〔P1〕

| 要确认 | 我们要映射到 |
|---|---|
| 有哪些岗位在系统里操作 | 4 个角色：`ADMIN` / `MANAGER` / `OPERATOR` / `VIEWER` |
| 谁负责审批 | `MANAGER`（P2 的 AI 建议审批人也在这里定） |
| 有多少人要用 | 决定要不要做用户管理界面（当前"不做"，见 S1-02） |
| 临时工怎么用系统 | 共用账号还是各自账号？共用的话审计追不到人 |

## 三、B 类：库存快照 〔P0〕

**要什么**：某个时点的**真实库存明细**（不是汇总）

**从哪拿**：现有系统导出 / 财务月末盘点表 / 手工台账

```
sku_code, location_code, batch_no, expiry_date,
qty_on_hand, qty_allocated, base_uom
```

**为什么要这个**（三个用途，缺一不可）：

1. **验证系统能不能表达现实**：如果他们的库存里有"半托""散箱""待检品"，看我们的 `qty_on_hand + batch_no + location_type` 能不能装下
2. **做系统初始化数据**：上线时要把真实库存录进去
3. **发现隐藏维度**：如果同一个 SKU 同一个库位有多条记录但**没有批次差异**，说明还有别的区分维度（如"状态"、"货主"）我们没建模

**现场重点**：

| 要确认 | 为什么关键 |
|---|---|
| 库存里有没有"货主"概念（同一批货属于不同客户） | 有的话是**第 9 个维度**，当前表结构装不下 |
| 有没有"待检/不合格/冻结"状态 | 对应 `QUARANTINE` 库位，或需要 `status` 字段 |
| 有没有负库存 | 有的话是管理问题，但系统 `ck_inv_on_hand >= 0` 会拒绝导入 |
| 批次号规则 | 谁编的、什么格式、有没有"无批次"的批次管理商品 |

## 四、C 类：单据样本 〔P0〕

**要什么**：**真实用过的纸质单据**（拍照或原件），不是空白模板

### C1｜入库单（5–20 张）

每张要能看清：单号、日期、供应商、明细行（商品/数量/批次）、收货人签字、手写批注

**从样本里要读出来的信息**：

| 看什么 | 对应我们的字段 | 判断什么 |
|---|---|---|
| 单号格式 | `order_no` | 我们的 `IN-日期-随机串` 要不要改成他们的规则 |
| 明细最多几行 | — | 假设 7「10 行以内」是否成立 |
| 有没有批次号列 | `batch_no` | 没有的话他们怎么做批次追溯 |
| 有没有效期列 | `expiry_date` | 有的话格式是什么 |
| 手写的批注写在哪 | `remark` | → 同时填「隐形字段清单」 |
| 有没有实收 ≠ 应收 | `qty_actual` vs `qty_required` | 部分收货的频率 |

### C2｜出库单（5–20 张）

同上，另外重点看：

| 看什么 | 判断什么 |
|---|---|
| 有没有"要求发运时间" | `requested_ship_at`，没有的话准时率指标算不了 |
| 有没有客户名称/编号 | `customer_name`，是否需要 `customer_no` |
| 有没有优先级标记（加急） | `priority` 字段的实际用法 |
| 拣货人怎么签字 | 对应拣货确认的审计 |

### C3｜其它单据（各 1–5 张，有就收）

| 单据 | 为什么收 |
|---|---|
| 退货单 | 当前系统**不支持退货入库**，看他们怎么处理 |
| 调拨单 | 当前不支持跨库位调拨（只能上架），看频率 |
| 盘点表 | 对应 S1-03 的「库存准确率」——有盘点表才可能做这个指标 |
| 异常/报损单 | 看不良品怎么记账 |

## 六、E 类：环境与规范 〔P1〕

| # | 要什么 | 怎么拿 | 用途 |
|---|---|---|---|
| 1 | **现有纸质单据的空白模板** | 要 1 套（入库/出库/盘点） | 我们的界面字段要能对上他们的习惯 |
| 2 | **库位标签照片** | 手机拍 | 决定扫码输入还是手输 |
| 3 | **商品包装照片**（尤其条码位置） | 拍 3-5 个典型商品 | 决定 PDA 扫码交互 |
| 4 | **PDA 设备型号** | 问 + 拍照 | 决定 H5 能不能跑（老旧 Android 版本会卡） |
| 5 | **仓库 WiFi 覆盖情况** | 问一句"哪些角落没信号" | 决定离线模式要不要做（当前**不做**，但如果死角多就是硬需求） |
| 6 | **货梯/通道限制** | 问一句 | 影响拣货路径算法（P3） |

## 七、脱敏规则（现场就要注意）

| 数据类型 | 怎么处理 |
|---|---|
| 客户名称 | 可保留（做测试数据需要真实感），但**不外传** |
| 价格、金额 | **不收**。我们只记数量，不收金额 |
| 供应商联系方式 | 不收 |
| 员工姓名 | 单据样本里出现可以，但录入系统时用"张三/李四"代替 |
| 手机号/身份证 | **绝对不收** |

> 收之前说一句："我们只记数量和流程，不涉及价格和客户隐私。" 这句话能降低对方的防备。

## 附：为什么按「表」来组织清单

这份清单不是按"现场有什么"组织的，是**按"我们的 8 张表需要什么真实数据"**组织的。

好处：**每收到一项，回来就能直接导进对应的表**，不用二次翻译。
